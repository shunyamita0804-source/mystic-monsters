## 盤の描画の修正（2026-10-19 P0・iPhone 試遊「最初だけ道がぼける」「道とマスがくっついていない」）

- 原因：海の世界の平面（preserve-3d）に、iPhone（Safari）では親（.rfw）の perspective が効かず、奥ほど地面と道がマス・モンスターより遠くへずれていた（手前だけ合う）。また近くの細かい層と遠くの層が同じ高さで、Safari では見る向きによって前後が入れ替わり、ぼけた遠くの層が上に出ていた。
- 修正：海の世界だけ、遠近を平面の transform の perspective() に入れる（js/proto/roadfirst-world.js の planeTf・同じ行列＝Chromium の描画は変わらない）。近くの層の区画は地面より 0.05 単位上（js/qa/road-1016.js の LIFT・海面 0.3 より下）。Chapter 1・3・4（平らな平面）は従来どおり。
- 検証用の Chromium では iPhone の症状は再現しない（描き方が違う）。iPhone での確認が必要。
- **2026-10-19 p0b2（iPhone 試遊の続き）**：
  - ルート A の START だけ数秒ぼける：近くの層が「遠くの層を全部描き終えるまで」始まらなかった（最初に開く盤は絵の読み込みと遠くの層の描画が長い）→ 絵の読み込みが終われば始める（js/proto/roadfirst-world.js の tick）。
  - 道の横の小さな杭の列：海上橋の欄干（sea_bridge_railing_left／right）を海面の帯として描いていた → 描かない（素材の読み込みは残す）。
  - 長い影：道の影を世界の南へ 7 単位ずらし・丸い端で描いていた → 1.5 単位・平らな端・少し薄く。
  - 道の重なり：狭い角度で集まる道は、広場の半径を帯どうしが離れる距離まで広げる（最大 44 単位）。広場どうしが重なる所は、影 → 床 → 縁石の順に全部描き、隣の広場の床の上には縁石を描かない。
  - 分かれ目の塔：道から約 26 単位離せる所が無い分かれ道には立てない（ルート C は立たない）。
  - START の港の門（ユーザー判断「道の上のまま大きさだけ直す」）：幅 52 → 75（アーチの口が道幅より少し広い 24 単位）・進む向きの右へ 9 単位（アーチの中心を道の中心に）・14 単位先。
- **2026-10-19 p0b3**：START の港の門をユーザー指示「角度をつけず道に対して正面に」で正面向きの派生に（assets/fields/ch2/art_1019/harbor_start_gate_front.webp＝正式の harbor_start_gate の左半分をアーチの中心で左右に折り返した絵・色は変えない・右の小屋は無い）。幅 58（アーチの口 24 単位＝絵の幅の 41%・中央）・14 単位先。

- **2026-10-20 通し試遊の品質改善**（ユーザーの iPhone 画像 IMG_5997〜6004・詳細は docs/fullplay_1020/REPORT.md）：
  - 円の広場（分かれ目・合流・START・行き止まり）は中心の1マスだけ：隣の地点を広場の中心から 38 単位以上離して道の上に並べる（tools/ch2/build_ch2_routes.py の CLEAR・tools/common/board_layout.py＝歩数・つながり・地点 ID は同じ）。経由点の角は半径 26 の円弧で丸めてから地点を並べる。
  - 広場の半径は 27（縁石の外のふち＝道の縁石と同じ幅）。道と広場は「縁石つきの帯と縁石の輪 → 道の床と広場の床」の2回で描く（重なった所の内側の縁石は床が覆う＝外のふちだけに縁石）。旧：半径を最大 44 まで広げ、広場の中にマスが並んでいた。
  - START の港の門：植え込みと階段（絵の行 376 から下）を切った派生 assets/fields/ch2/art_1020/harbor_start_gate_open.webp（色は変えない）・幅 72（アーチの口 29.5 単位＞縁石の外のふち 27）・START の広場の出口（27 単位先）・本線の最初のマスへ向ける・前後は地面の位置で決める。ルート C は START が分かれ道（港の大通りと岸壁が狭い角度）＝門は大通りが岸壁から約 50 単位離れる S01_02 の先（幅 68）。
