## 2. 向きの切り替え（試作の仕組み）

- 画面の上での進む向きを 45° ごとの 8つに分ける。境目の近く（±10°）は直前の向きを保つ（ちらつかない）。
- 向きを変えるときは隣の向きを1つずつ通る（1つ 70ms）。歩く位相（何コマ目か）は続ける・足もとの位置は全コマ同じ・伸縮・回転・クロスフェードはしない。
- 180° の向き直り（出発で後ろを向く・止まって正面へ）は、前回と逆の回り方＝来た向きへ戻るように回る（毎回1回転しない）。
- 止まると正面へ向き直る（その場で体を回す）。
- 4コマの速さは 8fps（1周 0.5秒）。正式の 8コマ 12fps は 0.67秒。`&qaWalkFps=`・`&qaWalkTurn=` で比較できる。

## 3. 技術の判断：中間の向き（斜め）は本当に要るか

- **後ろから追うカメラ（従来）**では、進む向きがいつも画面の上へ回るので、歩いている間はほぼ背面だけ。斜め・横が出るのは曲がり角と止まる・出発するときの向き直りだけ。＝今の 8コマ（正面・背面）でも成り立つ。
- **C案カメラ（向きを歩く間は止める）**では、道が曲がると画面の上で斜め・横へ歩く。正面・背面だけだと、横へ歩くのに正面を向いたまま（貼り絵が滑る）になる。＝**C案を採るなら、斜め前・斜め後ろ（と横）が要る**。
- 中間の向きの絵が無いまま正面 ↔ 背面を切り替えると、1コマで 180° 裏返る（ステッカーの裏返し）。5方向があれば 3つの間の向きを通して回せる。
